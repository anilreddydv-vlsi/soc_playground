Testbench parts

Each part has one job. A testbench only finds a bug if every part on the path from stimulus to check is there. Try removing one and running again.

DV corner

Tests follow the design

The tests on this page are generated from your address map. Add a block and the tests check it too. Real testbenches do the same with a register model generated from the register spec.

Directed tests aim; random tests explore

Reset, register and map tests check things you thought of. Random tests hit corners you did not, but only coverage tells you what they actually reached.

Checks need observation

The scoreboard can only compare what a monitor saw. Without the APB monitor, nobody records which registers were touched, so register coverage stays empty.

Assertions catch protocol bugs

Some bugs never change the data: a burst that crosses 4 KB, an unfair arbiter, PADDR moving during a wait. Only assertions on the bus signals see them.
