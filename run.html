Out-of-order reads

An AXI master can send a second read before the first one returns. Each read carries an ID (ARID). A slow memory and a fast memory finish at different times, so the data can come back in a different order. RID on the data tells the master which request it answers.

How a transfer travels

Master asks

The CPU puts an address on the AXI address channel (AWADDR for a write, ARADDR for a read) and raises VALID. If the DMA is also asking, the arbiter decides who goes first.

Decoder picks a slave

The interconnect compares the address with every window in the address map. No match means the default slave answers DECERR.

Memory answers on AXI

SRAM answers in a cycle or two. DDR waits its read latency before the first data beat. A burst moves several beats for one address.

Bridge converts to APB

For a peripheral, the bridge runs an APB setup cycle and an access cycle, plus one cycle per wait state, then gives the AXI response. That is why peripherals are slower.

Peripheral acts

Writing a register can do something: send a UART byte, light an LED, start the DMA. Reading can return status, such as a timer count.

Response returns

Every transfer ends with a response: OKAY, SLVERR (the slave refused it) or DECERR (nobody is at that address).
